# 用户资料编辑交接

GET/PUT `/sdkapi/user/profile` 沿用 SDKAPI v2 签名与登录鉴权。

- nickname：1–30 字，去掉首尾空格。
- gender：0 不透露、1 男、2 女。
- birthday：YYYY-MM-DD 或 null；1900 年起，不得晚于当前上海日期。GET 返回日期字符串，避免时区偏移。
- email：最长 254 字符的联系邮箱或 null；只用于资料展示，不用于登录，不表示邮箱已验证。
- PATCH 语义：未提交的字段不修改，生日和邮箱允许 null/空字符串清除。
- 邮箱只存业务服务器，不转发 Peer。昵称/性别沿用原有 Peer 同步。

部署前运行项目数据库迁移流程，新增 `002-user-email.mjs`。先迁移数据库，再部署接口，最后发布 App。2026-09-23 已按用户要求在线上执行此迁移，确认 email 为可空 VARCHAR(254)、迁移版本检查通过、服务健康正常；此次只升级数据库，未部署资料接口代码。

App 仅在 GET 返回 email 字段后开放邮箱输入，避免旧服务静默忽略保存。旧账号邮箱默认 null。回退旧服务可保留新增列，避免删除已填邮箱。
