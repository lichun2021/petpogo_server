# 积分到期机制重构方案

## 一、总体思路

将现有的「两列整数余额 + 每周一覆盖重置」模型，重构为**积分批次（batch）模型**：
- 每一笔赠送积分都成为一条独立记录，带自己的 `expire_at` 到期时间。
- 只有付费计划的赠送积分是永久积分（不过期）；签到、免费计划积分都是有期限的。
- 到期批次在读取余额时惰性失效（沿用现有的惰性策略，不引入 cron）。
- AI 消费按「先到期先扣」顺序扣减批次。

### 2. 新建 t_points_config —— 只定义「积分类型」
```sql
CREATE TABLE IF NOT EXISTS t_points_config (
  id          INT          PRIMARY KEY AUTO_INCREMENT,
  type_code   VARCHAR(32)  NOT NULL UNIQUE COMMENT '类型标识（程序内引用）',
  name        VARCHAR(64)  NOT NULL COMMENT '后台显示名',
  expire_days INT          NOT NULL DEFAULT 0 COMMENT '有效期天数，0=永不过期',
  sort_order  INT          NOT NULL DEFAULT 0,
  status      TINYINT      NOT NULL DEFAULT 1,
  updated_at  DATETIME     ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB COMMENT='积分类型配置表（只定义类型与有效期，数量在各业务表配）';

INSERT IGNORE INTO t_points_config (type_code, name, expire_days, sort_order) VALUES
  ('permanent', '永久积分', 0, 0),
  ('plan_free', 'Free计划积分', 7,  1),
  ('plan_pro',  'Pro计划积分',  30, 2),
  ('plan_promax','ProMax计划积分',30,3),
  ('checkin',   '签到积分',   7,  4);
```
说明：`expire_days=0` 即永久。计划类积分类型独立（不同计划可有不同有效期），签到统一一个类型。

### 3. 新建 t_user_points_batch —— 积分批次（核心表）
```sql
CREATE TABLE IF NOT EXISTS t_user_points_batch (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id       BIGINT NOT NULL,
  type_code     VARCHAR(32) NOT NULL COMMENT '引用 t_points_config.type_code',
  granted_amount INT NOT NULL COMMENT '发放时的数量',
  remaining     INT NOT NULL COMMENT '剩余可用数量',
  expire_at     DATETIME NULL COMMENT '到期时间，NULL=永不过期',
  reason        VARCHAR(100),
  ref_type      VARCHAR(30) COMMENT 'checkin/plan_order/admin_adjust',
  ref_id        VARCHAR(50),
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_expire (user_id, expire_at),
  INDEX idx_user_type (user_id, type_code)
) ENGINE=InnoDB COMMENT='用户积分批次表（每笔赠送一条，独立到期）';
```

### 5. t_plan 表改动（第 613-632 行）

## 三、后端工具层重构

### server/utils/points.ts（完全重写核心逻辑）

移除 `ensureWeeklyReset` 的"覆盖重置"语义，改为：

**新增 `ensureWeeklyGrant(userId)`**（惰性每周发放，累加不覆盖）：
1. 计算本周一。
2. 读 `t_user.plan_type` + **计划是否过期**（修复 bug：读 plan_expire_at，过期则视为 Free）。
3. 若 `last_weekly_grant_week < 本周一`：按当前有效计划的 `weekly_points_amount` 调用 `grantPointsBatch(..., type_code=weekly_points_type_code, expire_days=从t_points_config读)` 发放一批新积分，更新 `last_weekly_grant_week`。
4. 每周一为幂等标记：本周已发过就跳过。

**新增 `getPointsTypeExpireDays(typeCode)`**：从 t_points_config 查 expire_days。

**新增 `grantPointsBatch(userId, amount, typeCode, reason, refType?, refId?)`**（替代旧 grantPoints）：
1. 查 `t_points_config` 拿 expire_days；expire_days=0 → expire_at=NULL，否则 now+days。
2. INSERT 一条 `t_user_points_batch`（granted_amount=remaining=amount）。
3. INSERT 一条 `t_points_log`（direction=获得，type_code，expire_at）。

**重写 `getPointsBalance(userId)`**（返回批次明细）：
1. 先 `ensureWeeklyGrant`。
2. 惰性失效：`UPDATE t_user_points_batch SET remaining=0 WHERE user_id=? AND expire_at IS NOT NULL AND expire_at<NOW() AND remaining>0`（可选：记一条失效流水）。
3. `SELECT SUM(remaining) ... GROUP BY 是否永久`，并 `SELECT * ... remaining>0` 返回批次明细数组。
4. 返回 `{ expiring(有期限合计), permanent(永久合计), total, batches:[{id,typeCode,remaining,expireAt,reason}] }`。

**重写 `spendPoints(userId, amount, ...)`（先到期先扣）**：
1. 先 `ensureWeeklyGrant`。
2. 失效过期批次（同上）。
3. 校验 `SUM(remaining) >= amount`，不足抛 402。
4. 查未消费批次，**ORDER BY (expire_at IS NULL) ASC, expire_at ASC**（有期限且早到期的在前，永久在后）。
5. 依次扣减 remaining，每扣一笔写一条 t_points_log（direction=消耗）。单笔可能跨多条 batch → 多条日志。

**保留向后兼容导出**：`grantPoints`（旧签名）内部转调 `grantPointsBatch`，避免大量调用点一次性改爆。`POINTS_TYPE_WEEKLY/PERMANENT` 常量保留映射（兼容旧 admin 手动调整接口）。

### server/utils/plan.ts —— applyPlan 改动
- 周积分不再"立即覆盖 points_weekly"。改为：开通时立即调用 `ensureWeeklyGrant` 或直接 `grantPointsBatch(weekly_points_amount, weekly_points_type_code)`（累加发一批），并置 `last_weekly_grant_week=本周一`（避免本周重复发）。
- 永久积分：`grantPointsBatch(permanent_points_grant, 'permanent', ...)`。

## 六、历史数据迁移（init.sql 内提供，生产手动执行）

提供一次性迁移 SQL（注释形式）：
1. 对每个存量用户的 `points_permanent`：插一条 batch（type_code='permanent', granted=remaining=余额, expire_at=NULL）。
2. 对每个存量用户的 `points_weekly`：插一条 batch（type_code 按其 plan_type 映射 Free/Pro/ProMax，expire_at=now+对应expire_days 或直接 now+7）。
3. 保留旧 points_weekly/permanent 列做备份，新逻辑全部走 batch。
